# Заметки к проекту

## Почему я выбрал именно так

### Backend на Python
- Просто и быстро - не нужны библиотеки
- `http.server` встроен в стандартную библиотеку
- Монолит в одном файле - легко читать код
- Изначально немного думал про Node.js но потом понял что Python проще

### Nginx вместо какого-то другого proxy
- Стандарт де-факто для reverse proxy
- Легкий alpine образ
- Настройка простая и понятная

### Docker Compose вместо Kubernetes
- Задание явно сказало - нельзя K8s
- Для такой маленькой задачи Compose идеален
- Локально удобнее тестировать

## Что я учитывал при разработке

1. **Health checks** - без них docker-compose не знает когда сервис готов
2. **Non-root пользователь** - это хорошая практика безопасности
3. **Service discovery через имена** - не нужно IP знать
4. **Только один порт наружу** - backend невидим с машины (безопасно)
5. **Логирование** - можно видеть что происходит через `docker-compose logs`

## Что можно улучшить в будущем

- Добавить environment переменные для конфига
- Свой Dockerfile для nginx (если нужны дополнительные модули)
- Volumes для логов (чтобы сохранить после контейнера)
- SSL/TLS (но для тестовой задачи не требуется)
- Rate limiting в nginx
- Гда будет больше микросервисов - можно масштабировать

## Команды которые помогали при разработке

```bash
# Собрать образ вручную
docker build -t backend:local ./backend

# Запустить контейнер один раз для теста
docker run -it --rm -p 8080:8080 backend:local

# Посмотреть что внутри контейнера
docker exec -it devops-backend /bin/sh

# Проверить сеть
docker network ls
docker network inspect devops-test-task_app-network

# Очистить неиспользуемые образы/контейнеры
docker system prune
```
